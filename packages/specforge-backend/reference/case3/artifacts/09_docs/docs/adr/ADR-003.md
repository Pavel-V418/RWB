# ADR-003. Обработка работы без сети в мобильном приложении

ADR (Architecture Decision Record) фиксирует выбор между альтернативами, обоснование и последствия.

## Контекст и постановка проблемы

Кладовщики часто работают в зонах с плохим покрытием сети. Система должна позволять фиксировать выдачу и возврат инструмента даже при отсутствии связи с сервером, чтобы не останавливать операционную деятельность.

## Статус

**ПРЕДЛОЖЕНО** | ПРИНЯТО | ЗАМЕНЕНО

## Альтернативы

### Вариант 1. Локальная база данных и очередь синхронизации (SyncQueue)

Плюсы:

- Полная автономность мобильного приложения при потере связи
- Данные сохраняются локально и отправляются на сервер при восстановлении связи
- Пользователь не прерывает работу

Минусы:

- Сложность разрешения конфликтов при синхронизации
- Необходимость реализации механизма детектирования восстановления связи

### Вариант 2. Блокировка операций при отсутствии связи

Плюсы:

- Простота реализации
- Отсутствие конфликтов данных

Минусы:

- Невозможность работы в полевых условиях
- Снижение эффективности работы кладовщика
- Не соответствует требованию FR-10

## Принятое решение

Реализовать локальное хранение операций в мобильном приложении с последующей синхронизацией через очередь SyncQueue. При конфликте (инструмент уже выдан на сервере) операция отклоняется, и пользователь получает уведомление.

## Последствия принятого решения

- Мобильное приложение содержит локальную базу данных
- Реализован механизм автоматической синхронизации при появлении сети
- Возможны конфликты данных, которые требуют ручного вмешательства или автоматического отклонения

## Ответственные

- Архитектор
- Мобильный разработчик

Связано: FR-10, FR-15, Q-03
