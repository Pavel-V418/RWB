# ADR-001. Где определяется платная зона

ADR (Architecture Decision Record) фиксирует выбор между альтернативами, обоснование и последствия.

## Контекст и постановка проблемы

Нужно определять въезд, выезд и смену зоны одинаково для реального GPS и демонстрационного маршрута; границы зон могут обновляться.

## Статус

**ПРЕДЛОЖЕНО** | ПРИНЯТО | ЗАМЕНЕНО

## Альтернативы

### Вариант 1. на сервере по потоку координат (PostGIS)

Плюсы:

- единые правила для всех клиентов
- границы обновляются без выпуска приложения
- журнал событий формируется в одном месте

Минусы:

- без связи зона не определяется
- нагрузка на сервер при большом числе автомобилей

### Вариант 2. на устройстве по загруженным полигонам

Плюсы:

- работает без связи
- меньше запросов к серверу

Минусы:

- логика дублируется в мобильном приложении
- нужна синхронизация полигонов
- демо-маршрут пришлось бы проигрывать на устройстве

## Принятое решение

Вариант 1: мобильное приложение передаёт координаты, backend определяет зону запросом ST_Contains по GIST-индексу; при потере связи приложение буферизует координаты.

## Последствия принятого решения

- Правила определения зоны едины для GPS и демо-режима
- Уведомление о въезде зависит от связи; офлайн работает только таймер окончания

## Ответственные

- Системный аналитик
- Архитектор
