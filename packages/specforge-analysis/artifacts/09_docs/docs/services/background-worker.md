# Сервис Background Worker

Паспорт по «Шаблону описания сервисов». Разделы, которые зависят от инфраструктуры, заполняются из `docker-compose.yml`, `.env.example` и `.gitlab-ci.yml` (заполняется участником DevOps в `artifacts/08_infra/`).

## Описание

Таймеры сессий (expiring/expired), публикация outbox в Kafka, создание уведомлений, проигрывание демо-маршрутов

| Тип приложения | .NET 10 BackgroundService |
| Прикладное ПО / Frameworks | .NET 10 BackgroundService |
| Системное ПО | Linux, Docker |
| Swagger | неприменимо |
| Архитектура | сервисная: компоненты в отдельных контейнерах, взаимодействие по REST и событиям |

Контейнер; для прототипа ограничения ресурсов не заданы.

## Отказоустойчивость

- Мягкий старт: после восстановления сервиса мобильные клиенты досылают буфер координат с паузой и ограничением частоты (429 + Retry-After)
- Отказ поставщика парковочных услуг не блокирует определение зон и уведомления; водитель может подтвердить оплату вручную
- Событие не теряется при сбое после записи данных: transactional outbox и повторная публикация
- Повтор координаты или запроса с тем же Idempotency-Key не создаёт дублей
- Контроль вводимых параметров: диапазоны координат, формат госномера, время фиксации не позже текущего плюс 5 минут

## Предельные ограничения работы сервиса

| Операция | Нагрузка | Время |
| --- | --- | --- |
| Проверка окончания сессий (таймер Background Worker) | раз в 30 секунд по всем активным сессиям | предупреждение не позже 1 минуты после наступления момента now = paidUntil − 10 мин |
| Публикация outbox в Kafka | до 50 событий/с (предложение) | лаг ≤ 5 с |

## Работа сервиса

Фоновые задачи и обработка событий: `parking.zone.entered`, `parking.zone.exited`, `parking.zone.changed`, `parking.session.started`, `parking.session.extended`, `parking.session.expiring`, `parking.session.expired`.

## Мониторинг

- Health checks /health/live и /health/ready у Backend API и Worker; метрики Prometheus: запросы, ошибки, лаг outbox
- Мониторинг ОС и Docker (zabbix-agent2) в прототипе не настраивается.

## Логирование

- Структурированные логи JSON (Serilog) с traceId и correlationId; координаты в логи не пишутся

## Сетевая связность

- к сервису: Kafka — события
- от сервиса: Kafka — публикует события
- от сервиса: PostgreSQL + PostGIS — SQL

## Доступы к сервису

- Учётные записи с ролями driver и dispatcher, JWT со сроком жизни 8 часов; водитель имеет доступ только к своему автомобилю
