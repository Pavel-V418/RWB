E2E-прогон стенда после прошлой правки Tracking: выезд из зоны по-прежнему не определяется.
Машина в зоне 514725 с активной сессией, POST /api/v1/vehicles/{vehicleId}/positions с двумя точками вне всех зон
(accuracyM не задан) → transition = "none", currentZone = 514725, сессия остаётся status = "active".

1. Причина: проверка `if (prevCandidate != null || currentCandidate != null)` отбрасывает ровно случай выезда —
   оба кандидата null («вне зон»). Убери это условие: переход подтверждается, когда есть предыдущая учитываемая
   точка (в пакете или в vehicle_positions) и её кандидат равен кандидату текущей точки (null == null тоже
   совпадение) и отличается от текущей зоны. Если предыдущей учитываемой точки нет совсем (первая точка
   автомобиля), перехода нет.

2. Въезд в соседнюю зону по одной точке на запрос (приложение шлёт точки по одной): первая точка в зоне B уже
   сохранена в vehicle_positions с zone_id = B. GetLastZoneBeforeAsync(vehicleId, point.RecordedAt) тогда
   возвращает B, и вместо changed получается entered. Последнюю зону ищи до ПЕРВОЙ из двух подтверждающих точек:
   recorded_at < recordedAt предыдущей учитываемой точки, zone_id IS NOT NULL, accuracy_m IS NULL или <= 100.
   Окно 300 секунд считай от этой последней точки в A до первой подтверждающей точки в B.
