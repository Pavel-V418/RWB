## 1. Назначение

Выдать инструмент сотруднику.

Транспорт: HTTPS (TLS 1.2+), HTTP/1.1. Схема взаимодействия: синхронный запрос — ответ. Формат тела: JSON, UTF-8.

## 2. Входные данные (Входящие параметры)

### Авторизация

JWT в заголовке `Authorization: Bearer <token>`; роль пользователя берётся из claims токена.

### Заголовки

| Наименование | Описание | Тип данных | Обязательность | Пример |
| --- | --- | --- | --- | --- |
| Authorization | токен доступа | string | да | `Bearer eyJhbGciOi…` |
| Content-Type | формат тела запроса | string | да | `application/json` |
| X-Correlation-Id | сквозной идентификатор запроса; если не передан — генерируется сервером | string | нет | `req-20261030-0001` |

### Параметры path

Отсутствуют.

### Параметры query

Отсутствуют.

### Модель данных тела запроса

| Поле | Описание | Тип данных | Обязательность | Варианты значений | Поле БД |
| --- | --- | --- | --- | --- | --- |
| toolId | — | string (uuid) | да | — | `issue_records.tool_id` |
| employeeId | — | string (uuid) | да | — | `issue_records.employee_id` |
| issueDate | — | string (date-time, ISO 8601) | да | — | `issue_records.issue_date` |
| returnDeadline | — | string (date-time, ISO 8601) | да | — | `issue_records.return_deadline` |

Если обязательное поле не передано или не проходит проверку — ответ 400 с перечнем полей в `errors`. Лишние поля отклоняются (`additionalProperties: false`).

- Кладовщик (`warehouse_keeper`)

Остальным ролям — ответ 403.

| HTTP Code | Описание |
| --- | --- |
| 400 | Ошибка валидации запроса |
| 401 | Нет или истёк токен доступа |
| 403 | Недостаточно прав для операции |
| 404 | Ресурс не найден: Инструмент не найден; Сотрудник не найден |

## 4. Описание алгоритма работы метода

**Основной сценарий:**

1. Проверить права роли warehouse_keeper
2. Валидировать входные данные: toolId, employeeId, issueDate, returnDeadline
3. Проверить существование инструмента
4. Проверить существование сотрудника
5. Проверить, что инструмент не выдан (статус не issued)
6. Проверить, что инструмент не забронирован другим сотрудником (если есть активное бронирование, employeeId должен совпадать)
7. Создать запись IssueRecord со статусом active
8. Обновить статус Tool на issued
9. Если есть активное бронирование для этого сотрудника, обновить его статус на fulfilled
10. Зафиксировать событие issued в MovementHistory
11. Зафиксировать действие в AuditLog
12. Опубликовать событие tool.issued в Kafka
13. Вернуть созданную запись IssueRecord

**Сценарий исключений:**

- Инструмент не найден → 404
- Сотрудник не найден → 404
- Инструмент уже выдан → 409
- Инструмент забронирован другим сотрудником → 409
- Некорректные входные данные → 422

**Кэширование:** не применяется.

**Производительность:** ограничение частоты запросов, превышение — 429 и `Retry-After`; таймаут обработки 30 с.
