# Репетиционный кейс: Выдача инструмента и оборудования со склада
## 1. Контекст и проблематика
На складах технических служб хранится дорогостоящий инструмент и оборудование: перфораторы, тепловизоры, измерительные приборы, лестницы. Бригады получают их на смену и возвращают после работ. Учёт ведётся в бумажном журнале, поэтому инструмент теряется, а кладовщик не знает, у кого он находится.
## 2. Цель
Создать систему учёта выдачи и возврата инструмента: мобильное приложение кладовщика со сканированием QR-кодов и web-интерфейс для руководителя склада.
## 3. Функциональные требования
Система должна:
- вести каталог инструмента: инвентарный номер, наименование, категория, склад, состояние;
- печатать QR-код для каждой единицы инструмента;
- позволять кладовщику выдать инструмент сотруднику, отсканировав QR-код инструмента и пропуск сотрудника;
- позволять бронировать инструмент на дату заранее; забронированный инструмент нельзя выдать другому сотруднику;
- фиксировать возврат инструмента с оценкой состояния: исправен, требует ремонта, утерян;
- контролировать срок возврата и показывать список невозвращённого инструмента;
- передавать события выдачи, возврата и списания в корпоративную систему учёта ТМЦ;
- показывать историю движения каждой единицы инструмента;
- работать в мобильном приложении при отсутствии связи на складе и синхронизировать операции после её появления.
## 4. Ожидаемые компоненты
- мобильное приложение на Kotlin для кладовщика;
- административный web-интерфейс на Angular;
- backend на C# / ASP.NET Core;
- PostgreSQL;
- Kafka для передачи событий во внешнюю систему учёта;
- документированный API и модель событий;
- Docker-окружение, тестовые данные, автоматизированные тесты, CI/CD-пайплайн.
## 5. Интеграции
Корпоративная система учёта ТМЦ принимает события из Kafka. Промышленный доступ не предоставляется, интеграция реализуется через mock-потребителя. Справочник сотрудников и номера пропусков загружаются из файла.
## 6. Демонстрационный сценарий
- руководитель склада добавляет инструмент и печатает QR-код;
- сотрудник бронирует тепловизор на завтра;
- кладовщик пытается выдать этот тепловизор другому сотруднику и получает отказ;
- кладовщик выдаёт тепловизор забронировавшему сотруднику без связи с сервером;
- после появления связи операция синхронизируется, событие выдачи уходит во внешнюю систему;
- срок возврата истёк — инструмент появляется в списке невозвращённого;
- сотрудник возвращает инструмент с отметкой «требует ремонта».
