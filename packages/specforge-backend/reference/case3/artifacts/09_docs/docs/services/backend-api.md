# Сервис Backend API

Паспорт по «Шаблону описания сервисов». Разделы, которые зависят от инфраструктуры, заполняются из `docker-compose.yml`, `.env.example` и `.gitlab-ci.yml` (заполняется участником DevOps в `artifacts/08_infra/`).

## Описание

REST API, бизнес-логика, аутентификация, авторизация, публикация событий в Kafka

| Название | Описание |

| Тип приложения | ASP.NET Core |
| Прикладное ПО / Frameworks | ASP.NET Core |
| Системное ПО | Linux, Docker |
| Swagger | [openapi.yaml](../contracts/openapi.yaml) |
| Архитектура | сервисная: компоненты в отдельных контейнерах, взаимодействие по REST и событиям |

## Требования к ресурсам

Контейнер; для прототипа ограничения ресурсов не заданы.

## Отказоустойчивость

- Система должна быть доступна 99.5% времени.
- При потере связи мобильное приложение должно сохранять операции локально и синхронизировать их после восстановления.
- Система должна корректно обрабатывать конфликты при синхронизации, отклоняя дублирующие операции.
- Данные должны быть защищены от потери при сбое сервера.

## Предельные ограничения работы сервиса

| Операция | Нагрузка | Время |
| --- | --- | --- |
| Выдача инструмента | 10 операций/сек | < 2s (P95) |
| Бронирование инструмента | 5 операций/сек | < 2s (P95) |
| Публикация события в Kafka | 10 событий/сек | < 500ms |

## Работа сервиса

Принимает запросы REST (JSON, HTTPS) по пути `/api/v1`: 22 методов, описание — в разделе API.

## Авторизация

JWT: запрос содержит заголовок `Authorization: Bearer <token>`, роль — в claims.

## Мониторинг

- Система должна мониторить доступность API и загрузку Kafka.
- Оповещения о сбоях должны отправляться администраторам в реальном времени.
- Мониторинг ОС и Docker (zabbix-agent2) в прототипе не настраивается.

## Логирование

- Все операции и ошибки должны логироваться с указанием уровня важности.
- Логи должны храниться не менее 30 дней для анализа инцидентов.

## Сетевая связность

- от сервиса: Kafka Broker — публикует события
- к сервису: Mobile App — REST /api/v1, HTTPS + JWT
- к сервису: Web UI — REST /api/v1 + обновления в реальном времени
- от сервиса: Database — SQL
- от сервиса: TMЦ Mock Consumer — адаптер, REST

## Доступы к сервису

- Доступ к базе данных должен быть ограничен только для сервисных аккаунтов приложения.
- Администраторы должны иметь доступ к журналу аудита для контроля действий пользователей.
