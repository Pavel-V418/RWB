# Известные ограничения

## Вне рамок прототипа

- Реальная оплата парковки и промышленный доступ к внешним сервисам (CON-06)
- Собственный платёжный механизм (CON-07)
- Интеграция с корпоративным SSO — в прототипе собственные учётные записи (Q-01)
- Push-уведомления через FCM — уведомления доставляются опросом API и показываются локально
- Управление справочниками водителей и автомобилей через интерфейс — данные загружаются seed-скриптом

## Внешние системы заменены mock-сервисами

- Открытые данные о парковочных зонах Санкт-Петербурга — Границы, номера и параметры зон
- GPS устройства / демонстрационный mock-маршрут — Координаты автомобиля
- Паркоматика (API) — Организации, автомобили, водители, зоны и парковочные сессии у поставщика

## Решения, принятые без ответа заказчика

| Вопрос | Принято |
| --- | --- |
| Q-01. Как входят водители и диспетчеры: собственные учётные записи или корпоративный SSO? | Собственные учётные записи, JWT, роли водитель и диспетчер |
| Q-02. Реальная оплата не выполняется, но система должна показывать «Парковка оплачена до 15:20». Откуда система узнаёт время окончания? | Водитель выбирает длительность при запуске, mock-поставщик возвращает paidUntil |
| Q-03. Вход и выход из зоны вычисляются на сервере по потоку координат или на устройстве? | На сервере (PostGIS), устройство только передаёт координаты |
| Q-04. Сессия начинается автоматически при въезде в зону или только после действия водителя? | Только после подтверждения водителем; при въезде — уведомление |
| Q-05. Использовать снимок открытых данных Санкт-Петербурга или демонстрационный набор зон? | Снимок открытых данных в seed-файле GeoJSON |
