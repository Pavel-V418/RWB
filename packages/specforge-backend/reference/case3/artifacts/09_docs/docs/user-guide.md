# Руководство пользователя

## Кладовщик

Кладовщик работает в мобильном приложении. Основная задача — фиксировать выдачу и возврат инструмента с помощью сканера QR-кодов и пропусков. Приложение работает без интернета, синхронизируя данные при появлении связи.

### Выдача инструмента сотруднику

1. Откройте раздел выдачи в мобильном приложении
2. Наведите камеру на QR-код инструмента
3. Система отобразит информацию об инструменте
4. Наведите камеру на пропуск сотрудника
5. Система проверит доступность инструмента
6. Подтвердите выдачу

Результат: Система создаст запись о выдаче. Если связь отсутствует, операция сохранится локально. Если инструмент забронирован другим, система покажет отказ.

### Возврат инструмента с оценкой состояния

1. Откройте раздел возврата в мобильном приложении
2. Наведите камеру на QR-код возвращаемого инструмента
3. Система найдет активную выдачу
4. Выберите состояние: «исправен», «требует ремонта» или «утерян»
5. Подтвердите возврат

Результат: Система закроет запись о выдаче и обновит статус инструмента. Если выбрано «требует ремонта», инструмент будет помечен для обслуживания.

### Синхронизация данных

1. Дождитесь восстановления связи с сервером
2. Система автоматически обнаружит связь
3. Система отправит накопленные операции на сервер
4. Проверьте уведомления об успешной синхронизации или ошибках

Результат: Операции из локальной очереди будут переданы на сервер. Если возник конфликт (инструмент уже выдан), операция будет отклонена, и вы увидите уведомление.

### Если что-то пошло не так

| Ситуация | Что делать |
| --- | --- |
| Система показывает «Инструмент не найден» при сканировании QR-кода | Проверьте, что QR-код принадлежит инструменту, добавленному в каталог. Убедитесь, что камера хорошо сфокусирована на коде. |
| Система показывает «Сотрудник не найден» при сканировании пропуска | Проверьте, что сотрудник присутствует в актуальном справочнике, загруженном администратором. Возможно, файл справочника устарел. |
| Система показывает «Инструмент забронирован другим сотрудником» | Выдача невозможна, так как инструмент забронирован. Предложите сотруднику забронировать инструмент на другую дату или свяжитесь с руководителем склада для изменения бронирования. |
| Система показывает «Нет активной выдачи для этого инструмента» при возврате | Проверьте, что инструмент действительно был выдан и не был возвращен ранее. Возможно, данные еще не синхронизировались с сервера. |

## Руководитель склада

Руководитель склада работает в web-интерфейсе. Основные задачи — управление каталогом инструмента, печать QR-кодов, контроль возвратов и просмотр истории движения.

### Добавление инструмента и печать QR-кода

1. Откройте раздел каталога в web-интерфейсе
2. Нажмите на действие добавления нового инструмента
3. Заполните поля: инвентарный номер, наименование, категория, склад, состояние
4. Сохраните запись
5. Система сгенерирует QR-код
6. Распечатайте QR-код и прикрепите к инструменту

Результат: Инструмент появится в каталоге. QR-код будет доступен для печати. Если инвентарный номер уже существует, система покажет ошибку.

### Контроль невозвращённого инструмента

1. Откройте раздел «Невозвращенный инструмент»
2. Система отобразит список инструментов с истекшим сроком возврата
3. Проверьте список и свяжитесь с сотрудниками для возврата

Результат: Вы увидите список просроченных позиций. Если невозвращённого инструмента нет, система покажет сообщение «Нет невозвращенного инструмента».

### Просмотр истории движения

1. Откройте каталог инструмента
2. Выберите конкретный инструмент
3. Откройте вкладку истории движения

Результат: Система отобразит хронологический список всех операций: выдачи, возвраты, изменения состояния. Если история пуста, будет показано сообщение «История пуста».

### Если что-то пошло не так

| Ситуация | Что делать |
| --- | --- |
| Система показывает «Инвентарный номер уже существует» при добавлении | Проверьте каталог на наличие дубликата. Используйте уникальный инвентарный номер для каждой единицы инструмента. |
| Система показывает «История пуста» | Это означает, что с инструментом еще не проводились операции выдачи или возврата. Это нормальное состояние для нового инструмента. |

## Сотрудник

Сотрудник использует систему для бронирования инструмента на нужную дату. Выдача и возврат выполняются кладовщиком, но сотрудник должен заранее забронировать инструмент, чтобы гарантировать его доступность.

### Бронирование инструмента

1. Откройте каталог инструмента в интерфейсе сотрудника
2. Выберите нужный инструмент
3. Укажите дату, на которую требуется инструмент
4. Подтвердите бронирование

Результат: Система проверит доступность. Если инструмент свободен, бронирование будет создано. Если занят, система покажет сообщение «Инструмент уже забронирован».

### Если что-то пошло не так

| Ситуация | Что делать |
| --- | --- |
| Система показывает «Дата не может быть в прошлом» | Выберите текущую или будущую дату для бронирования. Бронирование на прошедшие даты невозможно. |
| Система показывает «Инструмент уже забронирован» | Выберите другую дату или другой аналогичный инструмент из каталога. |

## Администратор системы

Администратор системы настраивает параметры работы, управляет справочниками и контролирует интеграции. Основные задачи — загрузка данных сотрудников и мониторинг передачи событий.

### Загрузка справочника сотрудников

1. Откройте раздел управления справочниками
2. Выберите действие загрузки файла сотрудников
3. Загрузите CSV-файл с данными сотрудников и номерами пропусков
4. Система проверит формат файла
5. Подтвердите импорт

Результат: Система импортирует данные в таблицу Employee. Если формат неверен, будет показана ошибка валидации. При успешной загрузке появится подтверждение.

### Мониторинг интеграции с системой ТМЦ

1. Откройте раздел мониторинга интеграций
2. Проверьте статус очереди событий Kafka
3. Убедитесь, что события передаются в mock-потребитель

Результат: Вы увидите статус доставки событий. Если Kafka недоступна, события будут сохранены локально для повторной отправки.

### Если что-то пошло не так

| Ситуация | Что делать |
| --- | --- |
| Система показывает ошибку валидации при загрузке CSV | Проверьте формат файла. Убедитесь, что все обязательные столбцы присутствуют и данные соответствуют ожидаемому формату. |
| События не передаются в систему ТМЦ | Проверьте доступность Kafka-брокера. Если брокер недоступен, события накапливаются в очереди. После восстановления связи они будут отправлены автоматически. |
