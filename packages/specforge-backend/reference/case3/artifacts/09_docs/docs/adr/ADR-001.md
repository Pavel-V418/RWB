# ADR-001. Выбор стека технологий для клиентских приложений

ADR (Architecture Decision Record) фиксирует выбор между альтернативами, обоснование и последствия.

## Контекст и постановка проблемы

Необходимо разработать мобильное приложение для кладовщиков и web-интерфейс для руководителей. Ограничения проекта требуют использования конкретных технологий для обеспечения совместимости с корпоративной инфраструктурой и навыками команды.

## Статус

ПРЕДЛОЖЕНО | **ПРИНЯТО** | ЗАМЕНЕНО

## Альтернативы

### Вариант 1. Kotlin (Mobile) и Angular (Web)

Плюсы:

- Kotlin обеспечивает нативную производительность и доступ к функциям Android (камера для сканера)
- Angular предоставляет строгую типизацию и компонентную архитектуру для сложного web-интерфейса
- Соответствует установленным ограничениям проекта

Минусы:

- Необходимо поддерживать два разных языка программирования (Kotlin и TypeScript/C#)
- Более высокий порог входа для разработчиков, не знакомых с этими фреймворками

### Вариант 2. React Native (Mobile) и React (Web)

Плюсы:

- Единый язык (JavaScript/TypeScript) для обеих платформ
- Большое сообщество и доступность разработчиков

Минусы:

- Не соответствует жёсткому ограничению на использование Kotlin и Angular
- Возможные проблемы с производительностью сканера в React Native по сравнению с нативным Kotlin

## Принятое решение

Использовать Kotlin для мобильного приложения и Angular для web-интерфейса. Это решение зафиксировано в ограничениях проекта и обеспечивает оптимальную работу с камерой на мобильных устройствах и стабильность web-приложения.

## Последствия принятого решения

- Команда должна владеть навыками Kotlin и Angular
- Обеспечивается нативная работа сканера QR-кодов в мобильном приложении
- Web-интерфейс будет иметь строгую структуру компонентов
