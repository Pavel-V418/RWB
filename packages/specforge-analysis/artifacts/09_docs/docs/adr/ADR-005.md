# ADR-005. Доставка событий между компонентами

ADR (Architecture Decision Record) фиксирует выбор между альтернативами, обоснование и последствия.

## Контекст и постановка проблемы

Журнал, уведомления и административный интерфейс должны получать события надёжно и без дублей.

## Статус

**ПРЕДЛОЖЕНО** | ПРИНЯТО | ЗАМЕНЕНО

## Альтернативы

### Вариант 1. transactional outbox + Kafka

Плюсы:

- событие не теряется при сбое
- нет события без изменения данных

Минусы:

- нужен фоновый публикатор
- доставка at-least-once требует идемпотентных потребителей

### Вариант 2. публикация в Kafka из обработчика запроса

Плюсы:

- проще

Минусы:

- потеря или дубль события при сбое между записью и публикацией

## Принятое решение

Вариант 1: события пишутся в outbox в одной транзакции с данными и публикуются фоновым процессом; потребители идемпотентны по eventId.

## Последствия принятого решения

- Задержка публикации до нескольких секунд
- Надёжный журнал событий

## Ответственные

- Системный аналитик
- Архитектор

Связано: FR-20, NFR-2
