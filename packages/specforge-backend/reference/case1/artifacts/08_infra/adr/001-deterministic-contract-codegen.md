# ADR-001. Код по контрактам генерируется детерминированно, а не LLM

## Контекст и постановка проблемы
Из OpenAPI и DDL следует много кода, который выводится однозначно: DTO с валидацией, маршруты контроллеров, роли,
EF-сущности, клиенты API для web и Android. Если его пишет LLM, каждый прогон даёт разный результат, ошибки в
сигнатурах всплывают только на сборке, а токены (лимит 30 000 в минуту на ключ) уходят на шаблонную работу.

## Статус
ПРИНЯТО

## Альтернативы

### Вариант 1. Весь backend и клиенты пишет LLM-агент
- Плюсы
  - один механизм для всего кода;
  - не нужно поддерживать генераторы.
- Минусы
  - недетерминированный результат: два прогона дают разный код, сравнивать нечего;
  - расход токенов на шаблонный код, при лимите 30k TPM это часы;
  - расхождения с контрактом (имена полей, коды ответов) находятся поздно.

### Вариант 2. Генераторы для однозначной части, LLM — только для доменной логики
- Плюсы
  - одинаковый вход даёт байт-в-байт одинаковый выход (проверяется `diff -r` двух прогонов);
  - контракт и код не расходятся по построению; клиенты web и Android получаются автоматически;
  - LLM получает узкую задачу — реализовать интерфейс `I<Tag>Api` — и маленький контекст.
- Минусы
  - генераторы нужно поддерживать и проверять на живом выходе архитектора;
  - нестандартные конструкции OpenAPI требуют доработки генератора.

## Принятое решение
Вариант 2. `generators/run-all.sh`: серверный контракт ASP.NET (`gen_aspnet.py`), EF-модели из DDL (`dotnet ef dbcontext scaffold`
со своими шаблонами T4), клиенты (openapi-generator 7.26.0, версия и контрольная сумма закреплены). Каждый шаг — шлюз
качества с `gate.json`. LLM-агент пишет только реализации `I<Tag>Api` и фоновые задачи.

## Последствия принятого решения
- Ошибки контракта ловятся сборкой до вызова LLM; агенту не нужно знать маршруты, роли и формат ошибок.
- Изменение контракта = перезапуск генераторов; реализация агента ломается на сборке, если сигнатура изменилась, и уходит на ремонт.
- Найденные на живых контрактах дефекты (allOf, prefixItems, GeoJSON, enum PostgreSQL) исправляются в генераторе один раз для всех кейсов.
