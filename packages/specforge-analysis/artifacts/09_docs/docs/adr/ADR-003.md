# ADR-003. Интеграция с поставщиком парковочных услуг

ADR (Architecture Decision Record) фиксирует выбор между альтернативами, обоснование и последствия.

## Контекст и постановка проблемы

Промышленного доступа к «Паркоматике» нет; поставщика нужно уметь заменить без изменения бизнес-логики (требование заказчика).

## Статус

ПРЕДЛОЖЕНО | **ПРИНЯТО** | ЗАМЕНЕНО

## Альтернативы

### Вариант 1. адаптер IParkingProvider и mock-сервис

Плюсы:

- замена поставщика — новая реализация адаптера
- mock задаёт сценарии ошибок для тестов

Минусы:

- дополнительный слой абстракции

### Вариант 2. прямые вызовы API поставщика из сервисов

Плюсы:

- меньше кода

Минусы:

- нарушает требование заменяемости
- невозможно без промышленного доступа

## Принятое решение

Вариант 1: доменный слой работает с интерфейсом IParkingProvider, в прототипе реализацию даёт Parkomatica Mock.

## Последствия принятого решения

- Подключение реального поставщика не затрагивает доменный слой

## Ответственные

- Системный аналитик
- Архитектор

Связано: FR-17, CON-08
