## 1. Назначение

Получить список пользователей.

Транспорт: HTTPS (TLS 1.2+), HTTP/1.1. Схема взаимодействия: синхронный запрос — ответ. Формат тела: JSON, UTF-8.

## 2. Входные данные (Входящие параметры)

### Авторизация

JWT в заголовке `Authorization: Bearer <token>`; роль пользователя берётся из claims токена.

### Заголовки

| Наименование | Описание | Тип данных | Обязательность | Пример |
| --- | --- | --- | --- | --- |
| Authorization | токен доступа | string | да | `Bearer eyJhbGciOi…` |
| Idempotency-Key | ключ идемпотентности: повтор с тем же ключом возвращает первый результат | string (uuid) | да | `6f1c2b7e-3d4a-4e5f-9a8b-1c2d3e4f5a6b` |
| X-Correlation-Id | сквозной идентификатор запроса; если не передан — генерируется сервером | string | нет | `req-20261030-0001` |

### Параметры path

Отсутствуют.

### Параметры query

| Наименование | Описание | Тип данных | Обязательность | Пример |
| --- | --- | --- | --- | --- |
| role | — | string (enum) | нет | `warehouse_keeper` |
| isActive | — | boolean | нет | `True` |
| page | — | integer | нет | `1` |
| pageSize | — | integer | нет | `1` |
| page | номер страницы, с 1 | integer | нет | `1` |
| pageSize | размер страницы, ≤ 200 | integer | нет | `50` |

Если необязательный параметр не передан, фильтр не применяется; некорректное значение — ответ 400.

### Модель данных тела запроса

Тело запроса отсутствует.

### Пример запроса

```http
GET /api/v1/users?role=warehouse_keeper HTTP/1.1
Host: localhost:8080
Authorization: Bearer <token>
Idempotency-Key: 6f1c2b7e-3d4a-4e5f-9a8b-1c2d3e4f5a6b


```

### Кому разрешено вызывать метод

- Администратор системы (`system_admin`)

Остальным ролям — ответ 403.

## 3. Выходные данные (Исходящие параметры)

### Успешная обработка запроса

| HTTP Code | Описание | Возвращаемая информация |
| --- | --- | --- |
| 200 | Запрос успешно обработан | page |

#### Модель данных тела ответа

Формат: страница `{items, page, pageSize, total}`.

| Поле | Описание | Тип данных | Обязательность | Поле БД / ограничения |
| --- | --- | --- | --- | --- |
| id | — | string (uuid) | да | `users.id`; — |
| username | — | string | да | `users.username`; до 50 симв.; regex `^[a-zA-Z0-9._-]{3,50}$` |
| role | — | string (enum) | да | `users.role`; `warehouse_keeper`, `warehouse_manager`, `employee`, `system_admin`; по умолчанию `employee` |
| employeeId | — | string (uuid) | нет | `users.employee_id`; — |
| isActive | — | boolean | да | `users.is_active`; по умолчанию `true` |
| createdAt | время создания | string (date-time, ISO 8601) | да | `users.created_at`; — |
| updatedAt | время изменения | string (date-time, ISO 8601) | да | `users.updated_at`; — |

Необязательное поле без значения возвращается как `null`; пустой список — `[]`.

#### Пример успешного ответа

```json
{
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "username": "j.doe",
      "role": "employee",
      "employeeId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "isActive": true,
      "createdAt": "2026-10-30T14:20:00+03:00",
      "updatedAt": "2026-10-30T14:20:00+03:00"
    }
  ],
  "page": 1,
  "pageSize": 50,
  "total": 1
}
```

### Неуспешная обработка запроса

| HTTP Code | Описание |
| --- | --- |
| 400 | Ошибка валидации запроса |
| 401 | Нет или истёк токен доступа |
| 403 | Недостаточно прав для операции |
| 500 | Внутренняя ошибка |

#### Модель данных тела ответа (application/problem+json, RFC 9457)

| Поле | Описание | Тип данных | Обязательность |
| --- | --- | --- | --- |
| type | URI типа ошибки | string | да |
| title | краткое описание для пользователя | string | да |
| status | HTTP-код | integer | да |
| detail | подробности | string | нет |
| code | машиночитаемый код бизнес-ошибки | string | нет |
| traceId | идентификатор для поиска в логах | string | нет |
| errors | ошибки валидации: `[{field, message}]` | array | нет |

#### Пример неуспешного ответа

```json
{
  "type": "/errors/400",
  "title": "Ошибка валидации запроса",
  "status": 400,
  "detail": "описание причины",
  "traceId": "00-4bf92f3577b34da6a3ce929d0e0e4736-01"
}
```

## 4. Описание алгоритма работы метода

**Основной сценарий:**

1. Проверить права роли system_admin
2. Применить фильтры
3. Получить пагинацию
4. Вернуть список пользователей

**Сценарий исключений:**

- Стандартная обработка ошибок (см. раздел 3).

**Кэширование:** не применяется.

**Производительность:** пагинация, pageSize ≤ 200; таймаут обработки 30 с.
