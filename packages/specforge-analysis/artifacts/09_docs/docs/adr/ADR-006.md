# ADR-006. Аутентификация пользователей

ADR (Architecture Decision Record) фиксирует выбор между альтернативами, обоснование и последствия.

## Контекст и постановка проблемы

Корпоративный SSO в прототипе недоступен, а доступ нужно разграничить по ролям.

## Статус

**ПРЕДЛОЖЕНО** | ПРИНЯТО | ЗАМЕНЕНО

## Альтернативы

### Вариант 1. собственные учётные записи и JWT

Плюсы:

- быстрый запуск прототипа
- роли в claims токена

Минусы:

- отдельное хранение паролей

### Вариант 2. OpenID Connect с корпоративным каталогом

Плюсы:

- единый вход
- управление учётками в каталоге

Минусы:

- нет доступа к каталогу в прототипе

## Принятое решение

Вариант 1 (принят по умолчанию на вопрос Q-01): локальные учётные записи, JWT с ролями driver и dispatcher.

## Последствия принятого решения

- Для промышленного использования нужна интеграция с SSO

## Ответственные

- Системный аналитик
- Архитектор

Связано: Q-01, SEC-01, SEC-02
